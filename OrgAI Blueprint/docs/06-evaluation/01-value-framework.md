# 价值评估框架：从目标到可验证结果

> 本文是供组织改写的最小方法，不是效果承诺。所有阈值、权重和示例均须按本组织任务、所在地和用途确认。

## 1. 先定义价值和归因

立项时由业务负责人写清：谁受益、当前流程和替代方案、希望改善什么、谁承担结果责任，以及评价期间。建议覆盖上线前基线期、试点期和稳定运行期；日期、季节、工作量、人员配置、政策和系统变更均记录。采用同一任务定义、分母、数据来源和计时规则比较 AI 辅助与现行方案。优先随机分组；不可行时用匹配样本或分阶段上线，并说明差异和局限。只把合理可归因部分记为项目效果，记录并发因素，不把同期变化全部归给 AI。

基线须在试点前测量，目标事先约定。建议记录绝对值及变化量、样本量、缺失值和不确定性；小样本结果先视为探索。保存指标定义、数据抽取日期和版本，以便复算。

## 2. 最小指标组

| 维度 | 例子与口径 | 决策用途 |
|---|---|---|
| 质量 | 知识查询：答复是否正确、有依据、引用是否支持结论、是否应拒答；文档处理：字段/段落正确率、遗漏率、需返工比例。按指标使用问题数、字段数或文档数作分母，按严重程度区分错误 | 确认结果达到任务要求；严重错误可设为门槛 |
| 运营 | 每件完成时间、吞吐量、积压、一次通过率、人工复核分钟数、转人工率、失败率 | 判断流程是否更顺畅，避免只看模型速度 |
| 风险 | 越权访问、隐私或机密暴露、错误建议被采纳、投诉、偏差、审计异常、回退次数 | 设不可突破的停止条件并追踪整改 |
| 客户/群众 | 满意度、首次解决率、等待时间、服务可及性、申诉及纠错完成时间 | 判断受服务者体验变化 |
| 公共价值 | 不同群体的覆盖、可及性、等待和错误差异；服务连续性、资源使用 | 与财务收益分开报告；分组须合法、必要且保护隐私 |
| 财务与能力 | 可核实现金收入/支出变化；员工实际转岗任务、培训和流程能力 | 现金收益须有财务依据；能力提升单列，避免强行货币化 |

## 3. 样本、分组与人工复核

先按业务任务抽样，纳入常见、边界、低频高影响和失败案例；标注抽样框、样本量、排除规则、期间及标签依据。样本不足以估计稀有严重风险时，不得据“未观察到”推断风险为零。知识查询按问题类型、资料新旧和访问权限分组；文档处理按文档类型、质量、语言和复杂程度分组。只有在有正当目的、权限和足够样本时才评估敏感群体差异，使用最小必要数据并限制访问。

建立由具备任务知识的复核者执行的盲评抽样：尽可能隐藏答案来自哪种方案；给出统一评分标准；高影响输出逐件人工确认，低风险输出按风险设抽检率。记录复核者、分歧、裁决、纠错及复核耗时。不得把“人类在环”当作自动安全保证，复核者须有时间、能力和拒绝/升级权限。

## 4. 两个示意场景

**知识查询：** 对同一组获准使用的问题，比较现有关键词搜索/人工查找与检索增强问答。记录找到有效版本比例、答复正确且有支持出处的比例、无依据断言率、拒答适当性、完成时间、复核分钟数及权限违规。按主题、文档版本、问题难度和用户权限分组。无法提供可核实依据时，应能转人工或不答。

**文档处理：** 对同一批获准样本，比较人工模板处理与 AI 辅助提取/起草。记录字段准确率、遗漏与严重错误、人工修改量、每件总耗时、例外转交率及完成量；按文档类型、扫描质量和复杂度分组。发布、签批、对外发送或影响个人权益的决定由授权人员负责。

## 5. 阶段决策流程

1. **立项：** 业务负责人和评估负责人定义基线、期间、样本、对照、质量门槛、风险底线、成本项、目标及停止条件；数据和用途未获确认则不进入真实业务试点。
2. **小范围试点：** 限定用户、数据、权限和任务；记录运行日志、错误、人工复核、工时和成本。评估负责人按预先约定周期复测，风险责任人审查事件与分组差异。
3. **评审：** 业务、技术/运营、数据/安全、风险/法务（按适用性）和财务共同查看证据及限制。质量或风险门槛未过、严重事件未闭环、成本不可承受时停止或暂停；指标有改善但证据不足时延长受控试点；质量与风险达标且净价值可解释时，有限扩大并继续监测。
4. **调整或停止：** 对失败原因指定责任人、期限和验证方式；调整模型、资料、流程、复核或权限后重新评估。重复未达门槛、无法控制风险或无可持续价值则停止，切回已批准的现行流程并完成数据和记录处置。

结论用“继续、调整、暂停、停止”之一，附证据、未解决事项、批准角色和下次复审日期；演示结果不作为上线证明。

## PPT 要点

- 先定基线、同口径对照、评价期间和归因边界，再谈效果。
- 同时看质量、运营、风险与服务/公共价值，按任务和群体检查差异。
- 人工复核要有标准、抽样、升级权和耗时记录。
- 预先约定继续、调整、暂停和停止条件，证据不足就保持受控试点。
